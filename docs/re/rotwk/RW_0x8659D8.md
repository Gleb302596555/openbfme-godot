## The collide interface (`module + 0x24`) and its vtable (`RW 0xC5D650`)

An `OpenContain` module object has five interface subobjects:

* `+0x00` main module vtable (`UpdateModule` / `BehaviorModule`),
* `+0x0C` `BehaviorModuleInterface` (slot `+0x00` `getBody` `RW 0x9F3A3C` -> `0`, slot `+0x04`
  `getCollide` `RW 0x64F3EA` -> `this ? module + 0x24 : 0`, slot `+0x08` `getContain`
  `RW 0x64F3FB` -> `this ? module + 0x20 : 0`, slot `+0x10` `getDie` `RW 0x64F41D` ->
  `this ? module + 0x28 : 0`),
* `+0x10` `UpdateModuleInterface`,
* `+0x20` `ContainModuleInterface`,
* `+0x24` `CollideModuleInterface` (vtable **`RW 0xC5D650`**),
* `+0x28` `DieModuleInterface`.

Therefore inside `CollideModuleInterface` methods where `ecx = esi = module + 0x24`:

* `esi - 0x24` is the `OpenContain` module base,
* `[esi - 0x20]` (`module + 0x04`) is `m_moduleData` (`const OpenContainModuleData *`),
* `[esi - 0x1C]` (`module + 0x08`) is `m_object` (the container `Object *`),
* `esi - 0x04` (`module + 0x20`) is the `ContainModuleInterface` subobject.

### Gate details

1. **KindOf bit at `template + 0x11F` bit `0x80` (`RW 0x8659EB`)**: `ThingTemplate`'s KindOf
   bitmask starts at `+0x108` (`RW 0x8657D8` in `OpenContain::getEntryPosition` tests the same
   bit). Byte `+0x11F` is byte index `0x11F - 0x108 = 23`, bit `0x80` is bit `23 * 8 + 7 = 191`,
   which is `TheKindOfNames[191] = "SHIP"` (`KINDOF_SHIP`). Ships use the shore-spot boarding
   path in `OpenContain::getEntryPosition` / `getEntryOffset` (`RW 0x8657D1` / `0x8657B6`) and
   `AIMoveToPositionAndEnterState` (`RW 0x751A8A` / `0x756452`), so `OpenContain::onCollide`
   returns early for `SHIP` containers.
2. **AI vslot `0x1FC` (`RW 0x865A00` -> `RW 0x664D12`, `enterTargetOf`)**:
   ```

                    eax == 0x31 ||               ; 49

                    return [ecx + 0x1c]->Object  ; RW 0x664D63 -> 0x8DBACE (goalObject)
   ```

   This is already ported as `AIUpdateInterface::enterTargetOf()` in
   `engine/src/GameLogic/Module/AIUpdate.cpp:1732`.
3. **Module vslot `0x4C` (`RW 0x865A11` -> `RW 0x867C40`, `tryToEvacuate` /
   `cleanupBeforeAdding`, `INFERENCE` on the C++ method name)**:
   Every `OpenContain` subclass keeps `RW 0x867C40` in main vtable slot `+0x4C` (`OpenContain`
   `0xC599D8`, `TransportContain` `0xC5A588`, `HordeTransportContain` `0xC5C240`,

## Interaction with the enter state machine (`RW 0x751A8A` / `RW 0x7515E1`)

When a unit is ordered into a transport (`MSG_ENTER` -> `aiEnter` `RW 0x66C609` -> state 56
`AIMoveToPositionAndEnterState` `RW 0x751A8A`, or directly `aiEnterObject` `RW 0x66C5A4` ->
state 15 `AIEnterState` `RW 0x7515E1`, or a horde via `HordeContain::enterContainer`
`RW 0x875DC3` -> state 52 `AIHordeEnterState` for the horde and `aiEnterObject` -> state 15
`AIEnterState` for each member):

1. In `AIMoveToPositionAndEnterState` (`RW 0x751A8A` / `RW 0x756452`), the container is not
   ignored as a pathfinder obstacle (`m_adjustsDestination = true` at `RW 0x751AEB`), so the
   pathfinder adjusts the move goal to the nearest passable cell outside the container's
   footprint. When that move finishes (`r == STATE_SUCCESS` at `RW 0x7565A0`),
   `AIMoveToPositionAndEnterState::update` issues `aiEnterObject(container, cmdSource)`
   (`RW 0x7565B7` -> `RW 0x66C5A4`), transitioning the unit into `AIEnterState` (state 15).
2. In `AIEnterState::onEnter` (`RW 0x7515E1`), `ai().mover().ignoreObstacle(container->getID())`
   (`RW 0x7516C8`) and `LOCOMOTOR_ALLOW_INVALID_POSITION` (`RW 0x7516D7`) let the unit step
   inside the container's footprint toward `getEntryPosition()` (the container's centre).
3. While the unit is in `AIEnterState` (state 15), `enterTargetOf()` (`RW 0x664D12`) returns
   `container`.
   * With **`CollidePickup = Yes`** (the default): on the first frame the unit's bounding
     circle overlaps the container's bounding circle, the collision pass invokes
     `OpenContain::onCollide(unit)` (`RW 0x8659D8`), which calls `addToContain(unit)`
     (`RW 0x865A48`) immediately on contact. For a transport, `TransportContain::onContaining`
     sets `DISABLED_HELD` (bit 3), and `AIEnterState::update` (`RW 0x75616E`) returns
     `STATE_SUCCESS`.
   * With **`CollidePickup = No`**: `OpenContain::onCollide` returns at `RW 0x865A3F` without
     taking the unit on contact. The unit continues walking in `AIEnterState::update`
     (`RW 0x756067`) until `m_move->update()` finishes at the entry position (`RW 0x756184:
     cmp eax, 0; je 0x7561fa`), and then enters via `AIEnterState::update`'s own
     `contain->addToContain(&obj)` call at `RW 0x7561EF`.
   * Without an enter order toward the container (`enterTargetOf() != container`):
     `OpenContain::onCollide` returns at `RW 0x865A08`, so a unit touching or walking past the
     transport is never taken in.
