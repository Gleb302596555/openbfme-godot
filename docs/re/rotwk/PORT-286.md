# PORT-286: кто пишет флаги доступности кнопок

Разбор для fork issue 668. Источник: RotWK 2.01 (`rw.py dis`); строки матрицы сгруппированы по действительному источнику флага. Имена экземпляров и строки INI остаются в локальном досье, проверки на них — в PR.

## Читатель и общий путь записи

- `ControlBar::getCommandAvailability` **RW 0x942733**: ветка `RW 0x94280D` вызывает **RW 0x942490** до выбора команды, кроме `SPECIAL_POWER`. В последнем случае после проверки модуля и готовности (`RW 0x94357A..0x9435BE`, пауза без положительного прогресса запрещает кнопку) вызов идёт из `RW 0x9435C3` или `RW 0x9435DC`. `RW 0x942490` проверяет непустой запрещающий набор (+0x1E0), затем разрешающий (+0x194); в обоих случаях `RW 0x6632E9` ищет **любое** пересечение. Запрещающий имеет приоритет. Это 19 слов объекта с +0x10C, не четыре слова с +0x124. Последний адрес — одно слово внутри маски. `WEAPONLOCK_SECONDARY` — индекс 0x91; `USER_1/2/3` — 0xB8/0xB9/0xBA; `USER_8/9` — 0x1CC/0x1CD (`RW 0xD9FAD8`).
- `xref` даёт 523 ссылки на уведомление **RW 0x68B53C**, 44 на изменение маски **RW 0x68D607**, 31 на установку **RW 0x5E3BA5**, 61 на снятие **RW 0x5E3B79** (включая неинструкционные совпадения). Уведомление само не ставит бит: передаёт маску drawable и уведомляет AI. Ветви ниже установлены по **производителю** маски, а не по имени состояния в Draw / AnimationState или по одному xref.
- **RW 0x68F1A8** направляет модификатор через contain vslot +0x7C, затем horde vslot +0x1D8 (**RW 0x870E50**, получатели отряда, затем его собственный пул), либо прямо в пул. **RW 0x805A8E**: неизвестный/подавленный список отвергается; длительность по умолчанию из списка; обновление записи с тем же индексом передвигает срок, не выдаёт Upgrade повторно (`RW 0x805C73`); новая запись устанавливает `ModelCondition`, снимает `ClearModelCondition` (`RW 0x805BEA`, `RW 0x805C1B`). **RW 0x80585F** снимает установленные флаги по истечении (`RW 0x8058F4`); ручное удаление — **RW 0x8052FB** (`RW 0x805375`). Путь работает и со списком без числовых `Modifier`.

## LOCAL-75: момент выдачи «Мудрости учёных»

`BruchtalGelehrter` запускает `WeisheitderGelehrtenWeapon` через `WeaponFireSpecialAbilityUpdate`. При попадании `WeisheitderGelehrtenWeaponWarhead` применяет `WeisheitderGelehrtenUpgrade` (`includes/weapon.inc`, **RW 0x90EAF9**: вызов **RW 0x68F1A8** на `0x90ECE0` с длительностью `-1`, т. е. из списка). В `includes/attributemodifier.inc` у списка `Delay:100` (1 кадр) и `Duration = 3000` (15 кадров). До исправления парсер терял `Delay:100`, и пул выдавал апгрейд прямо при попадании (**RW 0x805C6C**, ветвь для нулевой задержки).

Корректный разбор не означает выдачу на следующем кадре: **RW 0x805CD8** сохраняет дедлайн, но при добавлении в спящий пул **RW 0x805CED** передаёт в **RW 0x850C32** длительность списка, где к ней прибавляется текущий кадр. При первом пробуждении, на 15-м кадре от попадания, **RW 0x80585F** собирает просроченный грант и выдаёт его через **RW 0x805A14**. Если пул по другой причине уже проснётся раньше, он проверит дедлайн раньше. `LOCAL-75` по-прежнему требует попадания в прежние 10 кадров наблюдения и дополнительно проверяет отсутствие апгрейда при попадании и выдачу не позже 15 кадров после него. Синтетический `PORT-286` отдельно держит точные границы для пустого пула: нет гранта на попадании, на +10 и +14; есть на +15. Расписание движка не менялось.
