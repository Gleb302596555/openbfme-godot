Branches: no victim → NOT_POSSIBLE. A CAN_ATTACK object that cannot path through gates attacking a STRUCTURE
needs a quick path to it (pathfinder RW 0x6F5F65). A WALL_UPGRADE victim whose wall module's slot 0 refuses →
NOT_POSSIBLE. Unless the type carries 0x10, a SPAWNS_ARE_THE_WEAPONS object asks its contain (slot 0x7C, the
spawner's riders): no contain, no slot-0x7C answer → NOT_POSSIBLE; the object with model condition 0x1BA and a
victim with KindOf word 5 bit 0x20 → NOT_POSSIBLE; the rider is slot 0x50 when the object's KindOf word 3 bit 0x40
is set, else slot 0x114(0xA4); no rider → NOT_POSSIBLE; else the **rider's** weapon set answers. Every other
object: its own weapon set (+0x34C).

## What the port has today

Ported by PORT-218 (issue 515): `Object::getAbleToAttackSpecificObject` (`Object.cpp`, the model condition 0x1BA and the
WALL_SEGMENT victim), `ObjectWeapons::getAbleToAttackSpecificObject` (every branch above except the ones listed in
S-7429) and `ObjectWeapons::getAbleToUseWeaponAgainstTarget`. The bool `canAttackObject` is now only a view on the
answer (`POSSIBLE` / `POSSIBLE_AFTER_MOVING`), `canAttackObjectNoShroud` its alias, and every consumer (the attack
machine, the closest enemy, the guard, the garrison, the turret, the order translator) asks the one path. Not ported
(stop S-7429): the attack-immunity byte, the gate path test and the wall module's veto of the object half, the
`SPAWNS_ARE_THE_WEAPONS` container / rider branch, the contain slots 0x4C / 0xDC, the locomotor's own move
test and the pitch of a pitch-limited weapon. The garrison slot 0x130 (RW 0x6C87A6 -> RW 0x6CBFF1) IS ported (it is
the port's `BehaviorModuleInterface::calcBestGarrisonPosition`), so a garrison's shot is measured from its best
garrison point, not from the container.

## Interpreting details worth naming in the code

* RW 0x6C91EB `not eax` + `test byte [victim+0x459], al`: the CONTESTING_BUILDING source tolerates exactly one
  immunity bit (bit 0), which in the port is `m_masked` (RW +0x459 bit 1). The immunity mask itself is not a port
  member — no 2.01/Ennorath INI writes it, see the stop line.
* RW 0x6C935A's source KindOf word 1 bit 0x800000 is MINE (kind 55): a MINE object may only attack a STRUCTURE
  (word 0 bit 7). The donor's `KINDOF_0x800000` names are unproved; the port resolves them by name.
* RW 0x6C937E's victim KindOf word 1 bit 4 is kind 36; the port resolves the bit by name (see the table row in the PR).
* RW 0x6C9422 source KindOf 0xCE is 206, whose port name is PASS_EXPERIENCE_TO_CONTAINER.
* RW 0x6C8804 / 0x6C8826 read weapon template + 0x2c (AimDelta), the port's `WeaponTemplate::m_aimDelta`.
