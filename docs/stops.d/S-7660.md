## Evidence and gap

RW 0x809370 iterates slot indices 0..7 through the GameInfo slot lookup, compares the slot's player key with the defeated player's key, checks the AI-slot predicate, and stores the current frame at +0x44 (RW 0x8093B6 .. 0x8093C5). RW 0x625F7C independently writes the current frame into the indexed GameLogic slot-frame array at +0x1CC.

The current port exposes `SkirmishGameSlot` as lobby/setup data, but the simulation-side `GameLogic` has no runtime slot object to update. `Player::setDefeatFrame` ports the ScoreKeeper end frame at Player +0x4CC and cannot stand in for the separate slot field. This needs runtime ownership/lifetime work before it can be implemented or tested faithfully.
