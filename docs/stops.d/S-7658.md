## Evidence and gap

The retail function has been read linearly with `rw.py dis`: RW 0x809271 first checks the current player's AI status (RW 0x6AA5B3), scans the cached players, looks up the Living World record by player id (RW 0x6B5DE0) and tests its +0x444 byte (RW 0x8092F8). It only enters the final computer-player kill loop at RW 0x809340 when an enemy record qualifies and no other cached player remains alive.

The port's `GameLogic` has no runtime `LivingWorldLogic` player-record handle alongside its `PlayerList`; the strategic `LivingWorldLogic::PlayerState` is a separate model. Until the identity/lifecycle bridge and the field's meaning are established, this branch cannot be ported without guessing. The existing S-1062 row remains narrowed to this and the slot-frame gap.
