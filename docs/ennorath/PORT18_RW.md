# Port 18 — hold fire, RotWK 2.01

Analysis of `game.dat` MD5 `daed3668006cd90f01c34e5a7da1901f`; addresses below were read with `tools/mod/rw.py dis`. No game data is included.

- `0x77B6C4–0x77B703`: object ID zero selects per-member inversion; otherwise the desired value is the inverse of the source's status `0x17`, or false if the source is not found. The related-object local `[ebp-0x18]` is initialized once to null at `0x77B6D7`.
- `0x77B71D–0x77B75A`: for each resolvable member, `0x68CBBC` checks for a behaviour interface at slot `0x68`. If present, `0x693C2D` must also be true before `0x68CBE2` gives an ID which is resolved and assigned to the related-object local. Otherwise this local is **not reset**: `0x77B821–0x77B82A` loops directly to `0x77B71D`. If the member is missing it is skipped. If the lookup following a true condition fails, the local is overwritten with null.
- `0x68CBC5–0x68CBE1`: walk the null-terminated behaviour list and ask each module's interface slot `0x68`; return true for the first non-null interface. `0x68CBEB–0x68CC07` performs the same walk and tail-calls that interface's slot 0 to get its object ID. SlavedUpdate's constructor `0x8A4F86–0x8A4F9A` sets behaviour vtable `0xC68850` and slaved vtable `0xC68820`; behaviour slot `0x68` is `0x8A18E0`, returning the interface at module + `0x20`, and its slot 0 `0x670216` reads the ID at module + `0x24`. The port's `SlavedUpdateInterface::of` implements this interface lookup. `SiegeDockingBehavior` also has a separate interface at +`0x20` (`0x85C9F2–0x85CA06`), but its behaviour vtable `0xC57C50` slot `0x68` is the null getter `0x851E97`; it is not an answer to this lookup.
- `0x693C2D–0x693C82`: a related interface and a resolvable related ID are required. Iterate all six live weapon slots of the **member** (`0x693C53–0x693C7B`, slot access `0x6C81B0`); a weapon with a template is decisive if `0x6CBAAB` returns true. That routine iterates the template's nugget list and calls nugget vslot `0x34` (`0x6CBABB–0x6CBAC9`). The base nugget vtable `0xC7AE40` has `0x9188EB` (false); SlaveAttackNugget constructor `0x910E8F–0x910E9D` sets `0xC7B9B0`, whose slot `0x34` is `0x8BD372` (true).
- `0x77B75D–0x77B779`: per-member mode always inverts its own status. With a source, skip an already matching member. Related-object discovery precedes this skip.
- `0x77B77F–0x77B7B1`: turning off sets the member status (horde kind uses `0x748650`, otherwise `0x62684D`) and, if the related local is non-null, directly clears that object's status. No AI is idled.
- `0x77B7B3–0x77B7EC`: turning on sets the member status by the same horde/non-horde distinction. If its AI exists, call AI vslot `0x1BC`; on true, call idle with player source (`0x77B7DA–0x77B7E8`). `0x77B7ED–0x77B81C` directly sets the related object's status and applies the same AI test and idle to it. The related object is not routed through the horde status path.
- The base AI vtable `0xC10590` slot `0x1BC` points to `0x662B3C`: if the current state exists, tail-call its vslot `0x24`; otherwise return true (`0x662B4D`). The attack/hunt implementation `0x740ECD` negates its state slot `0x20`; `0x742DD0` checks the nested machine's idle state. This is not equivalent to the port's `isAttacking()` state-ID test. The port exposes the base state-slot path as `isStateActive()`.

Scope caveat: the code-pointer scans in this analysis found the SlavedUpdate behaviour vtable and twelve AI vtables similar to the base, all with the same slot `0x1BC`; this is not a proof that no other class overrides either interface. Any unconfirmed class-specific behaviour remains a stop, not an inferred fix.
