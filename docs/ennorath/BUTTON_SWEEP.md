# Проверка всех кнопок Ennorath (матрица)

Первый рабочий шаг порта, решение владельца 2026-11-02 ([план](../ENNORATH_FACTION_PLAN.md), этап E2). Матрица отвечает на вопрос, который не видит таблица классов: что происходит, когда игрок нажимает каждую кнопку каждой фракции. Её результат решает, какие подсистемы из [SUBSYSTEMS.md](SUBSYSTEMS.md) брать первыми.

Статус: [ ] **ЗАНЯТО — Claude, 2026-11-02**. Есть первый срез: прогон `unitsOf` на данных мода, тест `ENNORATH sweep units`, только отчёт.

## Первый срез, 2026-11-02

Запуск: `OPENBFME_SWEEP_OVERLAY=<install мода>`, `OPENBFME_SWEEP_FACTION=FactionRohan`, `OPENBFME_SWEEP_MAP=map mp fall back 8p` (в кэше карт мода нет `fall back 4p`), `FACTB_ONLY=<часть имени>` для отдельных объектов, тест `--test-case="ENNORATH sweep units*"`.

Рохан, 98 строк: 65 прошли; 22 кнопка тактики, которая открывает радиальное меню (S-289); 11 к разбору:

| Итог | Строк | Кнопки |
|---|---:|---|
| `NO-RULE`, пробел проверки | 5 | `ModelConditionSpecialAbilityUpdate` (`Command_SpecialAbilityHornGamling`, `Command_SpecialAbilityHamaSeiteanSeite`), `InvisibilitySpecialPower` (`Command_SpecialAbilityWaldfhrer`), `SpecialDisguiseUpdate` (`Command_DisguiseEowynEdain`), `ReplaceObjectUpdate` (`Command_SpecialAbilityRadagastConvertEnemy`) |
| `NO-EFFECT`, кандидаты на ошибку | 3 | `Command_SpecialAbilityGeheimeWege`, `Command_PorterExtinguishFire`, `Command_TheodredReparaturarbeiten` |
| `NO-FIRE` | 1 | `Command_Repair` у `RohanPorter` |
| Не открылась | 2 | `Command_SpecialAbilityRohanTraitors`, `Command_SpecialAbilityTheodenAusbeutesteuer` у `RohanOldMan` |

Что срез уже дал: падение из-за `Racoon_Replacement`, которого нет в данных мода (исправлено, `ReplaceObjectUpdate`).

Чего срез пока не видит:

- **Покрытие.** 98 кнопок против 422 по графу: `factb::inventory` не раскрывает формы, смены набора команд, призывы и здания. Часть разницы это завышение графа; сколько именно, не измерено.
- **Звенья 3, 8 и 9** не реализованы.

Вывод пока осторожный: массовой поломки на уровне «нажал, сила сработала, эффект есть» в этих 98 строках нет. Жалобы владельца, вероятно, лежат в непокрытых формах и в звеньях 3, 8, 9. Следующие шаги: звенья 3 и 8, затем инвентарь.

## Звено 10, 2026-11-02

Для силы, которая сработала: кнопки на панели, доступные до нажатия, не должны остаться `Restricted` через 600 кадров (2 минуты игры). Только прогон на данных мода (`OPENBFME_SWEEP_OVERLAY`). Кнопки, ушедшие с панели, не оцениваются: смена формы меняет набор. Смотрится текущая страница панели.

- До исправления: `Command_SpecialAbilityGhanMeditation` даёт `STUCK`, `Command_SpecialAbilityGrausamerGiftpfeil` и `Command_SpecialAbilityWaldfhrer` заблокированы.
- Причина общая, не в этом герое: истёкший модификатор не снимался (стоп S-633), его условие модели оставалось навсегда. Медитация ставит `STONED`, эти кнопки выключаются по `DisableOnModelCondition = STONED`. Это касалось любого модификатора с условием модели и сроком, в моде и в чистой игре.
- Исправление: перенесены RW 0x80585F и 0x8052FB (`AttributeModifierPool`). После него на всём Рохане `STUCK` нет. Итоги остальных строк таблицы выше не изменились. В игре владелец ещё не проверял.

## Зачем

- Больше половины достижимых кнопок мода (1449 из 2809) это `SPECIAL_POWER` и `SPELL_BOOK`. Проверки «нажал → есть эффект» для них на данных мода нет.
- Сценариев `ENNORATH scenario` 10, минимум три из них по названию проверяют только данные.
- Сбои способностей у разных героев могут иметь общую причину, а могут не иметь. Пока это не измерено, это главное неизвестное порта.

## На чём строим

Новую систему не пишем. Для чистой игры такие прогоны уже есть ([FACTA](../FACTA.md), [FACTB](../FACTB.md), [FACTC](../FACTC.md)):

| Что есть | Где | Что делает |
|---|---|---|
| `EffectProbe` | `engine/tests/test_hud_factb_units.cpp` | по классу модуля силы определяет, что должно измениться в мире, сравнивает состояние до и после; класс без правила называет и считает ошибкой |
| `HudGame` | `engine/tests/FactbRig.h` | партия с настоящим HUD, принимает мир и фракцию |
| `unitsOf`, `heroesOf`, `fightsOf`, `damageOf`, `spellBookOf`, `fortressOf` | `test_hud_factb_units.cpp` | прогоны по всем юнитам, героям, книге и крепости через нажатия |
| `ControlBar::unportedPresses` | `engine/src/GameClient/ControlBar.h` | счётчик нажатий, которые движок не умеет выполнять |
| `ennorathscenario::World` | `engine/tests/EnnorathScenario.h` | мир RotWK + BFME2 + мод, загруженный без изменения мода |
| `SimulatedAudioDevice` | `engine/src/Common/Audio/` | позволяет проверить запрос звука без устройства |

Что мешает применить их сразу (прочитано в коде, сами прогоны на моде не запускались):

- прогоны берут мир из `hudtest::shared()`, а там нет мода, и этот вызов вшит в тела функций;
- цели подобраны по именам чистой игры, например `MordorFighterHorde` в строке 162 и `REQUIRE(faction == "FactionWild")` в строке 3049;
- карта `map mp fall back 4p` задана в `HudGame`; нужно проверить, что мод её не заменяет.

## Что проверяем для одной кнопки

Каждое звено записывается отдельно. Важно первое, на котором цепочка оборвалась.

| № | Звено | Как проверяем |
|---:|---|---|
| 1 | Кнопка видна и доступна при своих условиях (уровень, наука, улучшение) | состояние `ControlBar` |
| 2 | Нажатие мышью | `ControlBar::pressButton`, настоящий клик там, где он возможен |
| 3 | Нажатие хоткеем | `HotKeyTranslator`: результат должен совпасть со звеном 2 |
| 4 | Режим цели и курсор | команда ждёт цель, `RadiusCursorType` найден, допустимая цель принимается, недопустимая отвергается |
| 5 | Сообщение ушло и обработано | нет роста `unportedPresses` |
| 6 | Сила сработала | перезарядка началась там, где она есть в данных |
| 7 | Есть эффект в мире | `EffectProbe`: урон, лечение, модификатор, объект, смена формы, смена оружия |
| 8 | Запрошены звук и FX | запрос к звуку и запуск FX из данных кнопки и силы |
| 9 | Способность закончилась чисто | состояния, модификаторы и условия модели сняты, эффект прекратился в срок |
| 10 | Другие кнопки снова работают | после окончания остальные кнопки объекта не заблокированы |

То, что глазами и на слух не заменить (вид, громкость, совпадение анимации), матрица не решает: она даёт владельцу короткий список таких строк.

## Второй вход: кнопки, которые нажимает логика

Те же кнопки нажимают ИИ (`AISpecialPowerUpdate`, 3977 записей) и улучшения (`DoCommandUpgrade`, 273 записи). Это отдельный путь: `Object::doCommandButton`. Для него проверяем отдельно, что нажатие не попадает в `unported` и даёт тот же эффект, что и нажатие игрока.

## Результаты одной строки

| Итог | Значение |
|---|---|
| `OK` | все применимые звенья пройдены |
| `NO-EFFECT` | сила сработала, в мире ничего не изменилось |
| `NO-FIRE` | нажатие отвергнуто или перезарядка не началась |
| `UNPORTED` | сработал счётчик неперенесённого; указать какой |
| `HOTKEY-DIFF` | мышь и хоткей дают разный результат |
| `STUCK` | после способности остались состояние или заблокированные кнопки |
| `NO-RULE` | у `EffectProbe` нет правила для класса: это пробел проверки, а не порта |
| `UNREACHED` | условия кнопки выполнить не удалось: возможно, граф завысил достижимость |
| `OWNER` | логика пройдена, остаётся вид или звук |

## Что на выходе

- Файл одной строки на кнопку в `workspace/ennorath-audit/local/sweep/<дата>/<фракция>.tsv`: фракция, объект, кнопка, тип команды, первое оборвавшееся звено, итог, модуль, сработавшие счётчики и стопы. В Git не входит.
- `docs/ennorath/SWEEP.md`, создаётся инструментом: только идентификаторы и числа, сводка по фракциям и по причинам (первое звено + класс модуля). Сверху самые массовые причины.
- Каждая причина привязывается к подсистеме из [SUBSYSTEMS.md](SUBSYSTEMS.md). Причина без подсистемы становится новой подсистемой.
- Числа кнопок из графа заменяются измеренными: `UNREACHED` отделяет настоящие кнопки от завышения графа. Это становится знаменателем в [README.md](README.md).

## Порядок работы

1. **Один герой, одна фракция.** Перевести прогон на мир с модом для одного героя Рохана. Рохан первым: у него больше всего объектов со способностями (112) и уже есть жалобы владельца, значит, результат можно сверить.
2. **Вся фракция Рохан**, все типы кнопок. Замерить время: если прогон слишком долгий для ночного, делить по фракциям.
3. **Правила `EffectProbe`** для классов, которых нет в FACT-прогонах, пока `NO-RULE` не перестанет быть заметной долей.
4. **Остальные 10 фракций.**
5. **Второй вход**: кнопки ИИ и улучшений.
6. **Счётчики в `gap_census.py`.** Сейчас он собирает модули, действия и условия скриптов. Добавить нажатия, ИИ (`aiUnported`), оружие (`unportedNuggets`) и `doCommandButton`, чтобы их показывала и живая партия.

## Правила

- Ожидаемый результат берётся из данных мода, никогда из самого порта.
- В коде движка нет списков фракций и объектов. В тестах имена допустимы только как данные выбора целей, и подбирать цели надо по свойствам из INI.
- Мод не правится, данные игры в Git не попадают.
- В движке на этом этапе допустимы только счётчики и отчёт. Исправления механик идут этапом E3, в своих ветках.
- Падения фиксируются файлом базы `engine/tests/data/ennorath/sweep_<фракция>.txt` (только идентификаторы и итог). Новая ошибка роняет тест. Исправленная строка требует убрать её из базы в той же ветке. Это ожидания теста, поэтому действует [PROCESS.md](PROCESS.md), раздел 7.
- `SKIP` не считается пройденным: без трёх установок прогон ничего не доказывает.

## Готово, когда

- Прогон есть для всех 11 фракций и обоих входов.
- `SWEEP.md` создаётся инструментом, и в нём каждая причина привязана к подсистеме.
- Доля `NO-RULE` и `UNREACHED` названа и каждая группа объяснена.
- [SUBSYSTEMS.md](SUBSYSTEMS.md) пересортирован по результатам; владелец видел новый порядок.

## Что не решаем этой проверкой

Качество визуальных и звуковых эффектов, совпадение с таймингами оригинала, сеть, сохранения, кампании. Проверка показывает, что цепочка работает, но не что она совпадает с оригиналом покадрово.
