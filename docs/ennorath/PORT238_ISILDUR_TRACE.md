## Always-on ring pulse: bounded synthetic result

Form `:1809–1818` declares `FireWeaponUpdate` with a single repeating `FireWeaponNugget`, zero offset and delay, weapon `IsildurRingauswirkungWeapon`; the trigger flags are omitted. `includes/weapon.inc:42427–42463` sets 5000 ms between shots, allies / not-similar and five modifier nuggets with radius 15000. The five modifier lists (`includes/attributemodifier.inc:8497–8525`) have zero duration; only list 4 contains an **active** `Upgrade = Upgrade_GondorForgedBlades Delay:103`, the four other Upgrade lines are commented. List 4's filter is `ANY +INFANTRY +CAVALRY -ARCHER +HORDE -STRUCTURE -HERO -MACHINE -DOZER -SHIP ALLIES`. Actual template equivalences, horde/member propagation and all five live nugget effects are not inferred from this scan.

BFME2 donor `Object/Update/FireWeaponUpdate.cpp` supplies a lead. In RW registration `0x659012` binds factory `0x64CBF7`, ctor `0x88F731` installs primary table `0xC629C8` and update interface table `0xC629BC`; update `0x88F554` checks optional gating and sends ready records to `0x6CF3D2`. The port implements the bounded path in `SpellEffectModules.cpp`; S-924 remains for the forced-weapon hosting/delivery inference. `AttributeModifierNugget` applies the modifier via `0x90EAF9 -> 0x68F1A8`, with port `Combat/WeaponDelivery.cpp`. Correction after merging main `c47a4984`: the old trace incorrectly assumed default separators for the optional tag. RW `0x80514C–0x805154` passes INI `+0x420` to the tokenizer; constructor `0x42CB02` initializes it to `0xBD3D20`, bytes `" \n\r\t=:"`, and `0x805163` compares the token to `Delay`. For literal `Delay:103`, the decoded value is `ceil(103 * 0.005) = 1` logic frame. Upstream PORT-286 (#668, merged as `eadaae0a`) already fixed this in `AttributeModifiers.cpp::parseUpgrade`; no duplicate fix here. RW `0x805CD8–0x805CF9` stores the delayed deadline and wakes the idle pool with the list duration; the grant is processed by `0x80585F` / `0x805A14`. Zero duration, pending update order, repeated refreshes and a real game still require validation rather than assuming every pool grants at a universal wall-clock instant. `Upgrade_GondorForgedBlades` is declared OBJECT (`upgrade.ini:1796–1799`).

`PORT-238 Isildur-style ring pulse*` uses a synthetic weapon with list-4 values, `Delay:103`, targets already registered in the partition and synthetic distinct templates. With a consistent isolated `3f0105c8` core/headers plus only the PORT-286 parser change applied to a replacement compilation unit, it passes 36/36: no grant at first impact, the allied non-archer infantry has the object upgrade after the next frame, allied archer, hero and enemy do not, and the non-one-shot pulse fires again. The same test against the unmodified matching `3f0105c8` core fails 2/36 (zero delay and immediate grant); this is a negative control for the **upstream** parser fix, not a fix by PORT-238. The whole isolated suite passes 21/21, 606/606 with that replacement compilation unit. This is not the post-merge current core; its full build remains pending. The fixture omits the other four nuggets, real template restrictions, level-up state, rendering, horde transfers and actual mod loading.
