# Port 243: body damage-state readers

The ActiveBody data table RW 0xC71D68 stores the duration fields at +0x1C/+0x20 and modifier strings at +0x30/+0x34. The object factory RW 0x65114B calls the constructor RW 0x8C3841, which installs the primary vtable RW 0xC71B78; slot +0x34 is RW 0x8C283C. RespawnBody constructor RW 0x8C547A calls that base constructor and installs RW 0xC724E0, whose same slot is also RW 0x8C283C; its body-interface vtable RW 0xC72430 dispatches damage to RW 0x8C3FA3. Its data constructor RW 0x8C5689 calls ActiveBody data constructor RW 0x8C373F.

* RW 0x8C2A5D computes the new health state at RW 0x8C2A75 and invokes slot +0x34 only if it changes (RW 0x8C2A7A–0x8C2A83); construction also invokes this at RW 0x8C39D0, and health changes at RW 0x8C327D.
* RW 0x69990F zeroes the module array at RW 0x699E91–0x699EA4, constructs each module at RW 0x69A3AA, and inserts it only afterward at RW 0x69A3B9. Thus RW 0x8C3841 applies the initial state before later modules exist; RW 0x68BDA5 finds only earlier modules. DONOR BFME2 0x00298EA9 (`Code/GameEngine/Source/GameLogic/Object/ObjectConstructor.cpp`) shows the same construction order.
* RW 0x8C283C: DAMAGED adds nonempty +0x30 with duration -1 and removes nonempty +0x34 (RW 0x8C2893–0x8C28B9); REALLYDAMAGED removes +0x30 then adds +0x34 with duration -1 (RW 0x8C2866–0x8C2891); other states remove both (RW 0x8C2852–0x8C2864 and 0x8C28A7–0x8C28B9). Calls use Object RW 0x68F1A8/0x68F259, including horde routing.
* RW 0x8C3FA3 attemptDamage records the old state, changes health, then notifies damage modules on change (RW 0x8C4389–0x8C43C1). Only in that change branch, a new DAMAGED state with nonzero +0x1C or REALLYDAMAGED state with nonzero +0x20 calls Object RW 0x6907F1 with disabled type 8 and expiry current frame plus duration (RW 0x8C43C3–0x8C441D). Healing RW 0x8C2FC1 has its own state-change notification but no such disable branch. Existing Object disabled state is already serialized and hashed.
* DONOR BFME2 0x004BE69C and 0x004BE8BD (`Code/GameEngine/Source/GameLogic/Object/Body/ActiveBody.cpp`) show the corresponding modifier switch and state change; the same file's damage path shows the two disabled-duration branches. RotWK instructions above are authoritative.

Port before change: `ActiveBody::updateDamageState` changes the state without invoking the modifier switch; `attemptDamage` notifies damage modules but omits the duration. Both fields are parsed in `ActiveBody.cpp`, and `RespawnBody` shares the body implementation. No conclusion that other readers do not exist is implied.
