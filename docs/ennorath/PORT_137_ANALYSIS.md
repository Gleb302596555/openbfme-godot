# Port 137: WAKE_AUTO_PICKUP

Ennorath's `MordorMountainTroll` uses `MordorMountainTrollCommandSet_Edain` and a button-driven `AutoPickUpUpdate`; its rock command set changes the visible slot. This is distinct from `MordorTrollupgrade`. No game data is embedded here.

* RW 0x94280D–0x942820 calls the common model-condition test for non-special-power commands; RW 0x942490–0x9424E3 checks both masks. RW 0x942A5C dispatches the WAKE_AUTO_PICKUP command to RW 0x942FC6: no contain or a horde contain is available; an ordinary contain is available only when empty (slot 0x114). DONOR BFME2 0x53BD66 `Code/GameEngine/Source/GameClient/GUI/ControlBar/ControlBarRappellerCount.cpp` cases 0x2D and 0x31.
* RW 0x9412F8–0x941330 sends message 0x45C and selects the first matching option in ONE, TWO, THREE order, or zero. RW 0x77B51F calls RW 0x76FB3F, which iterates the selected group and calls RW 0x68C8DE on each object; that function walks modules, checks each auto-pickup interface's number, and calls its wake slot only for matching numbers. RW 0x8993FC sets both wake flags. DONOR BFME2 `ControlBarCommandProcessing.cpp`, `GameLogicDispatch.cpp` and `AutoPickUpUpdate.cpp` corroborate the route; RW is authoritative.
* RW 0x89994B–0x899995 searches terrain and invokes the grab power at the returned position. RW 0x8540D4–0x854112 materializes a tree via RW 0x68449B. By owner decision these steps were assigned to a separate task. LOCAL-42 (issue #353) has since landed tree materialization and its grab / pickup callers on main; this port does not duplicate or bypass that work. Joint in-game verification is still pending.
