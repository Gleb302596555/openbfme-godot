# PORT-238: Gollum ring routes (partial trace)

Literal sources are the extracted Ennorath 1.9.8.3 INI archive (MD5 `c53b6dea885cab044f80e783565f41f3`), with paths below relative to `data/ini` except `data/scripts`. No independent comparison with 1.9.8.4/1.9.8.5, effective inheritance/load, gameplay or visual validation has been made.

## Declared routes, not a gameplay capture

* `object/neutral/neutralunits.ini:927` defines `NeutralGollum` with `GenericCommandSet`, a 600-health body, fear/emotion modules, a 2000 ms active camouflage `InvisibilityUpdate`, and three `SlowDeathBehavior` death masks: ordinary `ALL -EXTRA_2 -EXTRA_3`, `NONE +EXTRA_2` and `NONE +EXTRA_3`. Its model is `CUGollum_SKN`; animations, stealth, audio, visible effects and child inheritance need actual validation.
* The `NeutralGollum_RingHero` child (`:1421–1443`) adds `CreateObjectDie` → `OCL_TheOneRing`, `ReplaceSelfUpgrade` on `Upgrade_RaiseShield` → `ClearGollumModel`, and wander AI. `OCL_TheOneRing` creates `TheDroppedRing` (`objectcreationlist.ini:9566`); shared attachment and its limitations are recorded in `PORT238_FRODO_TRACE.md`. The declaration is not proof of initial spawn, unique ring state, or death/replace outcome in the live mod.
* Both `NeutralGollum_RingStealer` and `NeutralGollum_RingStealerFrodo` declare two separate `CreateObjectDie` modules: `ALL -EXTRA_2 -EXTRA_3` → respective stealer OCL; `NONE +EXTRA_2` → respective carrier OCL (`neutralunits.ini:1540–1551`, `:1645–1654`). The four OCLs in `includes/objectcreationlist.inc:9026–9067` **directly** create their named Gollum objects, not the similarly named `CreateGollum...Egg` objects; `ObjectNames` egg references on two carrier lines are comments. The OCLs specify `DestinationPlayer = PlyrCreeps`, fade and `WaypointSpawnPoints = SpawnPoint_SkirmishGollum_`. Destination/team, map waypoints, spawn location, uniqueness and fade were not exercised by this trace. Separate egg objects in `object/projectile.ini:3884–4007,6134–6158` do declare a 10000 ms lifetime and later OCLs, but the similarly named direct OCLs do not thereby acquire that delay.
* The ordinary stealer explicitly equips `GollumAttack` (`neutralunits.ini:1486–1493`), whose declared damage uses `NORMAL` (`weapon.ini:9508–9528`), not `GollumRingstehlenAttacke` by name. The Frodo stealer explicitly equips `GollumRingstehlenAttackeFrodo` with `OnlyAgainst = PRIMARY GANDALF` (`neutralunits.ini:1585–1594`). Its weapon declares `RadiusDamageAffects = ENEMIES ALLIES SELF`, three different damage nuggets including delayed `EXTRA_2`, and an attribute modifier (`includes/weapon.inc:17571–17618`). These filters and amounts alone do not establish actual targeting, who is killed, removal of the victim's upgrade or whether an extra ring is created.
* The Frodo stealer names `NeutralGollum_RingStealerFrodoFunctions`; `data/scripts/scriptevents.xml:962–964` associates `OnSlaughtered` with `NeutralGollum_RingStealerSlaughtered`, whose body calls `ObjectRemoveUpgrade(other, "Upgrade_RingHero")` (`data/scripts/scripts.lua:1318–1320`). The normal stealer list has commented event lines; do not infer execution merely from the function definition. XML loading, effective binding, container selection and the actual arguments are untested here. S-129's general list still describes OnSlaughtered as unwired, but the newer PORT-55 path specifically dispatches it for an ordinarily consumed object with the container as arg 0 (`GarrisonContain.cpp:1776`, S-6010); neither observation proves this mod route runs.

## Bounded synthetic test

`PORT-238 Gollum-style death types select one creation list` creates a synthetic victim with the same two `DeathTypes` masks and two distinct direct creation lists. A NORMAL kill produces one synthetic thief, EXTRA_2 one synthetic bearer, EXTRA_3 neither. It passes **24/24 assertions** on matching core/headers `3f0105c8` plus separately compiled upstream PORT-286 parser; isolated `PORT-238*` is **31/31 cases, 1951/1951 assertions**. In an isolated negative fixture, removing only `-EXTRA_2` from the ordinary mask yields two thief-count failures (**22/24**): this is a fixture-sensitivity control, not an engine-fix control. RW `CreateObjectDie::onDie` `0x888F04` checks the DieMux (RW `0x85FED5`) and invokes OCL `0x5F0126`; current main includes PORT-237's shared context forwarding. This test uses direct `kill`, a simple source-player OCL and no `SlowDeathBehavior`, weapons, PLAYER owner selection, waypoints, Lua, real objects or client. No conclusion about end-to-end theft, death-animation timing, duplicates or visual/audio behavior follows from it.

Other shared limits include S-530 (unported OCL features), S-324 (client death presentation), S-129 (Lua/event coverage), plus the other PORT-238 stop list. This is a partial Gollum inventory, not closure of the audit.
