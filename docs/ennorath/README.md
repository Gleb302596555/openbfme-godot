# Порт Ennorath: с чего начать

Цель: Ennorath 1.9.8.4 на движке OpenBFME ведёт себя так же, как на RotWK 2.01. Мод не правится, чиним общий механизм движка.

**База: Ennorath 1.9.8.4 с 2026-11-20 (до этого 1.9.8.3 с 2026-11-15, 1.9.8.2 с 2026-11-04, 1.9.8.1 с 2026-11-03; решения владельца).** 1.9.8.4: владелец положил новую папку `RotWK/` и патч-ноут с разделом 1.9.8.4. Изменились только пропатченный pySAGE `game.dat` (md5 `ad5ff959…`: реплеи, блокировка чата, выбор всех зданий, все разрешения, выбор 30 / 60 кадров, исправление обхода лимита зданий, Война Кольца на 8 игроков; для разработчиков CommandSet 33 → 64 места и 1152 → 5120 улучшений), новый `############enrth_data_wotr8.big` (три сценария Войны Кольца) и `lang/englishpatch201.big`; INI мода (`____enrth_data.big`) и текстуры те же, что в 1.9.8.3. Тестовая копия `workspace/mods-en/Ennorath/install` обновлена (файлы 1.9.8.3 — `workspace/backups/ennorath-1.9.8.3`), песочницы 1–4 получили `ennorath_1.9.8.4_update.zip`. Пункты раздела 1.9.8.4 — поведение пропатченного exe, а не `game.dat` 2.01: работа только форка (PROCESS 12); в порте уже есть переключатели 64 мест CommandSet (`edain-unchained.commandset-limit`, MODS-3) и больше 1152 улучшений (S-5303), Эннорат их пока не включает. 1.9.8.3: владелец положил в `RotWK/` новые `____enrth_data.big`, `lang/englishpatch201.big` и `############bugfixtextures.big` и обновил патч-ноут `docs/ennorath/Ennorath mod Patch Note.docx` (в нём есть раздел 1.9.8.3). Тестовая копия мода `workspace/mods-en/Ennorath/install` обновлена, файлы 1.9.8.2 лежат в `workspace/backups/ennorath-1.9.8.2`. 1.9.8.3 ещё и патчит `game.dat` (60 кадров в секунду, горячие клавиши чата Ctrl+C / V / X / A); эталоном адресов `RW 0x…` остаётся ванильный `game.dat` 2.01 (md5 `daed3668…`, `workspace/games-en/Vanilla_(2.01)/install/game.dat`; `RotWK/game.dat` с 1.9.8.4 пропатчен). Решение владельца 2026-11-15: 60 кадров порт не берёт (у него своя система кадров), горячие клавиши чата берёт (P-128). Ожидания тестов и проверки берутся из 1.9.8.4. Патч-ноут считается правдой о том, как мод должен работать: каждый его пункт проверяется, и расхождение порта с ним — ошибка, которую ищут. Но последнее слово за файлами мода (INI, скрипты, данные архивов текущей версии) и за кодом RotWK: если пункт патч-ноута расходится с файлами мода, верны файлы, а расхождение записывается в отчёт. В патч-ноуте действует самый новый раздел, сейчас 1.9.8.4; более старое описание той же механики уже неверно. Реестры фракций и таблицы, снятые до смены базы, сделаны на старой версии (многие — на 1.9.8): при расхождении с текущими файлами мода верны файлы. Файлы мода и патч-ноут не входят в Git, ветки их не несут: их не копируют и не заменяют из других веток и деревьев.

## Порядок работы

Решение владельца, 2026-11-02:

1. [Проверка всех кнопок](BUTTON_SWEEP.md): что происходит при нажатии каждой кнопки каждой фракции.
2. [Подсистемы](SUBSYSTEMS.md): порт механизмов, сгруппированный по причинам.
3. Проход по фракциям A–G из [плана](../ENNORATH_FACTION_PLAN.md) как приёмка, а не поиск ошибок.

Записи в [PROBLEMS.md](PROBLEMS.md) это симптомы: они привязываются к подсистемам и закрываются вместе с ними. Прямое поручение владельца важнее этого порядка.
