# Порт Ennorath: с чего начать

Цель: Ennorath 1.9.8.3 на движке OpenBFME ведёт себя так же, как на RotWK 2.01. Мод не правится, чиним общий механизм движка.

**База: Ennorath 1.9.8.3 с 2026-11-15 (до этого 1.9.8.2 с 2026-11-04, 1.9.8.1 с 2026-11-03; решения владельца).** 1.9.8.3: владелец положил в `RotWK/` новые `____enrth_data.big`, `lang/englishpatch201.big` и `############bugfixtextures.big` и обновил патч-ноут `docs/ennorath/Ennorath mod Patch Note.docx` (в нём есть раздел 1.9.8.3). Тестовая копия мода `workspace/mods-en/Ennorath/install` обновлена, файлы 1.9.8.2 лежат в `workspace/backups/ennorath-1.9.8.2`. 1.9.8.3 ещё и патчит `game.dat` (60 кадров в секунду, горячие клавиши чата Ctrl+C / V / X / A); эталоном адресов `RW 0x…` остаётся ванильный `game.dat` 2.01 (md5 `daed3668…`). Решение владельца 2026-11-15: 60 кадров порт не берёт (у него своя система кадров), горячие клавиши чата берёт (P-128). Ожидания тестов и проверки берутся из 1.9.8.3. Патч-ноут считается правдой о том, как мод должен работать: каждый его пункт проверяется, и расхождение порта с ним — ошибка, которую ищут. Но последнее слово за файлами мода (INI, скрипты, данные архивов текущей версии) и за кодом RotWK: если пункт патч-ноута расходится с файлами мода, верны файлы, а расхождение записывается в отчёт. В патч-ноуте действует самый новый раздел, сейчас 1.9.8.3; более старое описание той же механики уже неверно. Реестры фракций и таблицы, снятые до смены базы, сделаны на старой версии (многие — на 1.9.8): при расхождении с текущими файлами мода верны файлы. Файлы мода и патч-ноут не входят в Git, ветки их не несут: их не копируют и не заменяют из других веток и деревьев.

## Порядок работы

Решение владельца, 2026-11-02:

1. [Проверка всех кнопок](BUTTON_SWEEP.md): что происходит при нажатии каждой кнопки каждой фракции.
2. [Подсистемы](SUBSYSTEMS.md): порт механизмов, сгруппированный по причинам.
3. Проход по фракциям A–G из [плана](../ENNORATH_FACTION_PLAN.md) как приёмка, а не поиск ошибок.

Записи в [PROBLEMS.md](PROBLEMS.md) это симптомы: они привязываются к подсистемам и закрываются вместе с ними. Прямое поручение владельца важнее этого порядка.
