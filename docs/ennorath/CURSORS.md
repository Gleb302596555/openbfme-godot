# Курсоры: что ставит оригинал (RotWK 2.01 + Эннорат 1.9.8.2)

Таблица по PROCESS 15.13: сначала оригинал, потом порт. Источники:
- код RotWK (`RotWK/game.dat`);
- `mouse.ini` Эннората. Своих файлов курсоров в моде нет, он берёт ванильные `data\cursors\*.ani`.

## Как выбирается курсор

1. **Наведение без выделения** (createMouseoverHint, RW 0x69FCFC .. 0x69FD73):
   - выбираемый объект, которым управляет локальный игрок (RW 0x68B749), — `Select`;
   - всё остальное — `Arrow`;
   - при непустом выделении наведение курсор не трогает (RW 0x69FD0C → 0x69FD7E): его ставит подсказка команды из пункта 2.
2. **Подсказка команды при выделении.** `evaluateContextCommand` (RW 0x81E60B, вызов при наведении на объект RW 0x8204F2, на землю RW 0x81FD3B) выдаёт номер подсказки. Номер превращается в курсор по таблице переходов `createCommandHint` (RW 0x6A4099).
3. **Номер курсора → имя:** таблица RW 0xD9E108. Имя → картинка: `mouse.ini` мода.

## Картинки

| Курсор | Номер | Картинка (Эннорат `mouse.ini`) | Как выглядит |
|---|---|---|---|
| Arrow | 2 | SCCPointer.cur | обычная стрелка |
| Move | 5 | SCCMove | зелёные стрелки, сходятся к центру |
| Select | 13 | SCCSelect | жёлтый пульсирующий квадрат |
| GenericInvalid | 12 | SCCNoAction.cur | «нельзя» |
| AttackObj / ForceAttackObj / ForceAttackGround / OutRange | 7 / 8 / 9 / 35 | SCCAttack | атака |
| AttackMove | 6 | SCCAttMov | атака с движением |

## Расхождение с наблюдением владельца (P-15, 2026-11-12)

Владелец помнит жёлтый квадрат (Select) при выделенных войсках над своими и союзными зданиями и войсками. По коду RotWK при выделении над ними получается:
- над войсками — Move (зелёные стрелки);
- над зданиями — GenericInvalid;
- Select — только над своей стеной, по которой ходят, в режиме атаки с движением над своим объектом и при выделенных производящих зданиях над объектом.

По PROCESS 15.13 агент сам не выбирает. Владельцу нужно проверить в оригинальном моде строки, где таблица расходится с его памятью.
