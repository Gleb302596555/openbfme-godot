It is not a test of all six timers, actual inheritance, save/load or real mod loading.

## Teleport chain

Ring StoreObjectsSpecialPower radius is 130 with `ChainedButton = Command_AlatarTeleportStoredListNewRing` (`evilalatar.ini:2331–2352`); its second worker is `TeleportToCasterSpecialPower` with min/max destination radii 10/100 and level-7 unpause (`:2354–2375`). The store template's `ObjectFilter` includes multiple unit kinds without an ALLIES-only clause (`includes/specialpower.inc:6609–6617`); the chained release template has `NO_FORBIDDEN_OBJECTS` with an allied filter and range 130 (`:6619–6628`). The chained button is hidden (`includes/commandbutton.inc:48473–48479`). This differs materially from the base's ally-only store template (`specialpower.inc:6567–6575`). Generic chained recharge is already covered by `PORT-261`; generic stored/fallback teleport and snapshot tests are `modgap2 store objects:*` and `modgap2 teleport:*`. The location gate is in `ActionManager.cpp` (`RW 0x82D2FD`, S-1874); none of those facts proves the actual HUD chain, the forbidden-location result or all target filters in the mod.

It checks stored order, two moved units, excluded structure/unattackable/outside targets and retained owners. **35/35 assertions**, isolated `PORT-238*` **34/34 cases, 2120/2120**, on matching core/headers `3f0105c8` plus separately compiled upstream PORT-286 parser, not current-main full executable.
