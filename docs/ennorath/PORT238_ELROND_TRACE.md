## Restoration's timer-refresh slot

The BFME2 donor `SpecialPowerTimerRefreshSpecialPowerSlot13.cpp` leads to a base `ApplyPowerToObject` followed by an object-wide refresh; it is not evidence of RW by itself. In RW, module registry reference `0x65B4E9` names factory `0x654884`; factory calls ctor `0x65197C`, which writes primary vtable `0xC0610C`. Its slot `+0x34` is `0x8C7B26`: base `0x89763B`, then `0x68BDF9` walks target modules and calls their `+0xC` interface slot `+0xB0`. SpecialPowerModule thunk `0x6519C2` reaches `0x896F99`, which skips paused/disabled, ability-in-progress and shared-timer cases and otherwise sets the ready frame to the current frame. Base area selection at `0x897BAB–0x897C47` uses the parsed filter, relationship, alive and (unless spell-book) same-map-status filters. `HeroAbilityModules.cpp::applyToVictim` and `SpecialPowerModules.cpp::refreshTimer` implement the bounded path; the already-ported shared mechanism has a synthetic `PORT-258` test. **S-920 remains open**: the port's base scan does not implement RW's same-map-status filter on this path, and other S-920 limitations still apply. The upstream PORT-252 off-map fix belongs to a different shared emotion-pulse path and does not close S-920 here.
