## Общая цепочка разбора (A)

- Регистрация блоков: данные PE `0xD98ABC` = строка `AudioSettings`, данные PE `0xD98AC0` = RW `0x44107A`; данные PE `0xD9EC24` = строка `CloudEffect`, данные PE `0xD9EC28` = RW `0x614FC9`. Связывание реестра INI-блоков видно в RW `0xBC2DCD`, RW `0xBC2DD2`, RW `0xBC2DE2`, RW `0xBC2DE7`.
- RW `0x44107A` — разбор `AudioSettings`: RW `0x4410B0` `mov eax,[0xDE42FC]`, RW `0x4410B5` `mov ebx,[eax+0x10]` — база хранилища полей; RW `0x4410C5` `push 0xBD7698` (данные PE: начало таблицы из 74 строк), RW `0x4410E8`/RW `0x4410E9` `push eax` / `push ebx`, RW `0x4410EC` `call 0x42D4B0`.
- RW `0x42D4B0` — общий диспетчер: RW `0x42D575` берёт смещение из дескриптора строки, RW `0x42D583` `add ecx,edx`, RW `0x42D585` `add ecx,[ebp+8]` (объект + offset), RW `0x42D58D` `call eax` — парсер пишет результат по адресу «объект + смещение строки».
- Парсеры (все RW): `0x42E558` bool → RW `0x42E571` `mov byte [ecx],al`; `0x42EC5E` int → RW `0x42EC77` `mov [ecx],eax`; `0x42ECB2` uint → RW `0x42ECFC` `mov [ecx],eax`; `0x42EEFA` процент→float → RW `0x42EF18` `fstp dword [eax]`; `0x42ED00` float → RW `0x42ED19` `fstp dword [eax]`; `0x42EE5E` строка → RW `0x42EE7D` `call 0x436030`.
- Владелец `+0x10`: RW `0x45E07A` `push 0xC08`, RW `0x45E093` `call 0x45C675` создаёт объект аудиоменеджера; thunk RW `0x4417C1` `jmp 0x45E06F` лежит в таблице фабрик (данные PE `0xBD8570`). RW `0x45C69A` `mov [esi],0xBDB550` (данные PE vtable), RW `0x45C6A9` обнуляет `[esi+0x10]`; RW `0x45CAA7` `push 0x204`, RW `0x45CABF` `call 0x440EE9`, RW `0x45CAD1` `mov [esi+0x10],eax` — объект настроек размером `0x204`. RW `0x440F63` ставит vtable настроек `0xBD83D0`; RW `0x440F69` / `0x440F6D` / `0x440F70` / `0x440F3C` / `0x440F77` / `0x440FAA` задают значения по умолчанию; RW `0x44100B` `push 0x1A`, RW `0x44100E` `lea edi,[esi+0xC4]`, RW `0x441014` `mov eax,0x3F800000`, RW `0x441019` `rep stosd` заполняют 26 float от `+0xC4` до `+0x12C`.
- Регистрация глобального указателя: RW `0x63B171` `push 0xDE42FC`, RW `0x63657B` `mov [esi],edi`, затем RW `0x63B17B` / RW `0x63B186` `call [eax+0x14C]` по объекту из `0xDE42FC`.
- Геттер RW `0x9F9F1A` (`mov eax,[ecx+0x10]; ret`) стоит в слоте `+0x134` vtable (данные PE `0xBDB684`). Он возвращает **указатель** на хранилище, а не значение поля, и как доказательство чтения поля не используется.

## Проверенные цепочки положительных вердиктов

### B. Массив `Global*ReverbMultiplier` (строки 1–19)

Данные PE: таблица `0xBD7698` содержит 25 строк с непрерывными смещениями `+0xC8`, `+0xCC`, … `+0x128` (строки данных PE `0xBD7868` … `0xBD79E8`), все с парсером `0x42EEFA`; 19 из них — поля этого issue, остальные 6 (`GlobalBathroomReverbMultiplier`, `GlobalAuditoriumReverbMultiplier`, `GlobalCaveReverbMultiplier`, `GlobalArenaReverbMultiplier`, `GlobalCarpetedHallwayReverbMultiplier`, `GlobalAlleyReverbMultiplier`) лежат между ними. Индекс строки `idx = (offset − 0xC4)/4` принимает значения 1…25. Конструктор RW `0x44100B` `push 0x1A` / RW `0x44100E` `lea edi,[esi+0xC4]` / RW `0x441014` `mov eax,0x3F800000` / RW `0x441019` `rep stosd` заполняет ровно 26 float начиная с `+0xC4`, то есть весь диапазон индексов 0…25.

Читатель RW `0x452754`: RW `0x452755` `mov esi,ecx`, RW `0x45276F` `call [0xBD0BD8]` получает индекс окружения, RW `0x452783` `test eax,eax` / RW `0x452785` `jl` / RW `0x452787` `cmp eax,0x1A` / RW `0x45278A` `jae` отсекают всё вне 0…25, RW `0x45278C` `mov ecx,[esi+0x10]` берёт хранилище настроек, RW `0x45278F` `fld dword ptr [ecx+eax*4+0xC4]` читает float по индексу. Следовательно каждое из 19 смещений достижимо этой одной инструкцией при своём индексе; отрицательного значения индекса и выхода за `0x1A` ветки не допускают.

Использование: RW `0x4527F5` `fmul [ebp+8]`, RW `0x45285C` / RW `0x45285F` `fmul`, RW `0x4528AD` `fmul`, RW `0x453328` `fmul`, RW `0x45B21D` `fmul` умножают прочитанный множитель на уровень эффекта; результаты уходят в RW `0x452812` `call 0x4A8534` и RW `0x452877` `call [0xBD0AFC]`. Вызывающие RW `0x452754`: RW `0x4527F0`, RW `0x452857`, RW `0x4528A8`, RW `0x453323`, RW `0x45B218` — все внутри RW `0x4527A8`; последний вызывают RW `0x45B2EC` (в RW `0x45B268`), RW `0x45BAA9`, RW `0x45BD04`, RW `0x45BEF8`, RW `0x45EEC0`, RW `0x45F09D`. RW `0x45B268` вызывается RW `0x45C10D` (в RW `0x45C047`); RW `0x45C047` — RW `0x45D9FE` и RW `0x46062D`.

INFERENCE: соответствие числового индекса конкретному названию окружения и тому, что вызов `[0xBD0BD8]` возвращает тип окружения, взято из имён полей, строк и порта. Непосредственно доказаны граница индекса, чтение `[настройки+idx*4+0xC4]`, умножение и передача результата в звуковой путь; «клиент» — статическая классификация звукового кода.
