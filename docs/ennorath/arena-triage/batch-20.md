# Триаж полей 20/25: RotWK 2.01 (`game.dat`) × 30 полей блока `GameData`

Issue [#30](https://github.com/Gleb302596555/openbfme-godot/issues/30). Ветка `arena/c1d6fa58-openbfme-godot`.
Образ: `workspace/RotWK/game.dat`, 11 346 944 байт, md5 `daed3668006cd90f01c34e5a7da1901f`. Все адреса ниже читаны
`python tools/mod/rw.py workspace/RotWK/game.dat dis <addr>` и записаны как `RW 0x…`.

Вопрос по каждому полю один: что с ним делает RotWK 2.01. Портировать в этой задаче нечего — меняется только этот файл.

## 1. Цепочка разбора (общая для всех 30 полей)

| звено | адрес |
|---|---|
| блок `GameData` в INI → запись регистрации в `.data` | RW 0xD9DEA4 (строка имени RW 0xBF3B60, обработчик RW 0x644148) |
| загрузка экземпляра | RW 0x644158 и RW 0x644185: `mov ecx, [0xDE4364]` |
| таблица полей | RW 0x6441A5 `push 0xBFF580`, RW 0x6441AA `push ecx` → движок RW 0x42DB80 |
| сама таблица | RW 0xBFF580: 457 строк по 16 байт {имя, функция разбора, userData, смещение}, конец RW 0xC01210 |
| второй путь к таблице | RW 0x643D5D (`mov eax, 0xBFF580; ret`), ссылки RW 0x6441A6 / RW 0x64423B (запись в RW 0x42DB80) |
| экземпляр GameData | глобал RW 0xDE4364 |
| умолчания конструктора | RW 0x6429E4 … RW 0x6438xx (например `ShowProps = 1` RW 0x6429E4, `RightMouseAlwaysScrolls = 0` RW 0x642A4E, группа курсорных частиц RW 0x6435E7–0x6436A4) |

Что четвёртый dword строки — именно смещение члена, проверено на полях с известными читателями: `Gravity` +0xC4,
`TimeOfDay` +0x134, `SellPercentage` +0xB94 — код читает ровно эти смещения от RW 0xDE4364.

## 2. Как искали чтения

1. Сплошной проход по `.text` (RW 0x1000–RW 0x7D0000, 2 701 800 инструкций): собраны все операнды памяти с
   displacement, равным смещению члена, — 28 323 адреса.
2. Отдельно собраны все инструкции, загружающие указатель из глобала RW 0xDE4364, — 1 293 адреса.
3. Для каждой пары (смещение, сайт) проверен поток данных: держит ли базовый регистр именно этот указатель
   (цепочки `lea`/`mov`, перенос через вызовы, сброс при посторонней записи в регистр). Чтением считается только
   такая пара; совпадение одного смещения — не доказательство, смещения вида 0x1C, 0x5D, 0xC0, 0xD8A… в других
   классах встречаются сотнями.
4. Контроль метода на заведомо читаемых полях: `TimeOfDay` +0x134 — 43 подтверждённых чтения, `Gravity` +0xC4 — 12,
   `DefaultCameraMaxHeight` +0xA0 — 2, `SellPercentage` +0xB94 — 1. Метод находит и единственного читателя, поэтому
   «подтверждённых чтений нет» — содержательное утверждение.
5. Собственная запись парсера в проход не попадает: движок RW 0x42DB80 берёт смещение из строки таблицы во время
   разбора, поэтому «обращений нет» ниже означает «нет обращений с константным смещением в коде»; запись разбора
   есть всегда, когда поле задано в INI.

`RotWK не использует` ставится, когда подтверждённых чтений нет вообще, а все обращения по смещению — либо
инициализация в конструкторе GameData (RW 0x6429E4–RW 0x6438xx), либо принадлежат другому классу (другая база;
проверено, что функция не загружает RW 0xDE4364), и аксессора с базой GameData тоже нет.

### 4.2 Что должно стать задачами TOP20

Сначала — то, что даёт механику (RotWK читает, порт разбирает и не использует):

1. **`PowerLimit`** (#11) — единственное чисто игровое поле пачки: предел силы игрока копируется в объект игрока (RW 0x631430 → RW 0x631436) в инициализации RW 0x6311ED. В порту `EconomySettings.cpp:166` значение разбирается и не используется.
2. **`ScoreKeeper_NormalVictoryRequiredScore` + `ScoreKeeper_NormalVictoryRequiredObjectivesPercentage`** (#18, #17) — одно задание: условие нормальной победы (RW 0x79E175, пороги +0x11AC и +0x11B0). В порту оба разбираются (`GameLogicSettings.cpp:272-273`) и не читаются.

Затем — клиентские, по убыванию видимости в игре:

3. **`ShowProps`** (#23) — пропуск отрисовки пропсов сцены (`false` в INI сейчас ничего не меняет в порту).
4. **`SoundsOn` + `SpeechOn`** (#26, #27) — гейты групп каналов 2 и 8 (RW 0x63C87D / RW 0x63C8D5); без них настройки звука в порте не действуют.
5. **`SkipMapUnroll`** (#25) — выключает вторую фазу загрузки карты (RW 0x91C177).
6. **`SelectionFlashHouseColor` + `SelectionFlashSaturationFactor`** (#19, #20) — пара к уже открытому п.12 TOP20 (вспышка drawable, RW 0x678FA7): флаг «цвет дома» и коэффициент пересвета.

Скорее «стоп» с адресами, чем перенос (в порте нет соответствующей подсистемы): **`ParticleScale`** (#10),
**`ParticleCursorParticleSize` / `ParticleCursorPerFrameSize`** (#5, #6) — курсорные частицы; **`StretchTerrain`** (#29) —
нарезка ландшафта на патчи; **`ShellMapName`** (#21) — фон меню/шелл-экран.

Остальные 16 полей — кандидаты на строку «RotWK тоже не использует» с адресами из таблицы (по образцу п.13 TOP20,
`Object/Browser`), а не на перенос.

### 4.4 Что не удалось и почему

- Входы нескольких функций не выводятся линейным декодированием от известных границ (внутри `.text` лежат таблицы
  переходов, декодирование по ним разъезжается): RW 0x4ABE02 (второе чтение `StretchTerrain`), участок RW 0x7BA9B8
  (`ShellMapName`), RW 0x63AD4F (звуковые гейты). Для вердикта это не важно: чтение и его эффект прочитаны
  по инструкциям и по потоку данных, а не по имени функции.
- Ни одного `не определено` не понадобилось: у 14 полей есть чтение с доказанной базой, у 16 — либо ноль обращений,
  либо только конструктор/чужой класс, и строки трёх полей (`ShowCollisionExtents`, `ShroudOn`, `StateMachineDebug`)
  в образе физически нет — эти три живут в `gamedatadebug.ini`, который мод и сам помечает как «только DEBUG/INTERNAL».
