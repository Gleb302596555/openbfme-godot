# Field triage 19/25 — результаты проверки 30 полей Ennorath 1.9.8.2 в RotWK 2.01 (game.dat)

Источник: issue #29 (`Field triage 19/25`). Бинарник: `workspace/RotWK/game.dat` (md5 `daed3668006cd90f01c34e5a7da1901f`, оговорка S-001 — community-modified image). Все адреса прочитаны через `python tools/mod/rw.py workspace/RotWK/game.dat dis|xref|str <addr>`.

Данные мода — из `ennorath-ini-1.9.8.2.zip` (все 30 полей заданы в `data/ini/gamedata.ini`, кроме #8/#9 — они в `data/ini/gamedatadebug.ini`).

Общие факты, на которых построены вердикты:

- Таблица полей блока `GameData` (gamedata): начало `0xBFF580` (рядом — `0xC01200`, последняя найденная строка `WaitToForceMemberToEnterDelay`). Строка таблицы = 16 байт `{name_ptr, parseFn, userData, offset}`; offset — смещение члена в объекте GameData. Парсер вызывается как `push 0xBFF580; push ecx; call 0x42DB80` при `ecx = [0xDE4364]` (RW 0x6441A5 и 0x64423A, функция разбора gamedata.ini 0x644152).
- Глобальный указатель на GameData: `0xDE4364` (запись при создании: RW 0x64234 `mov [0xDE4364], ecx`; очистка в деструкторе RW 0x643DA0/0x643DA7). GameData выделяется размером `0x1254` (RW 0x64420A `push 0x1254`).
- Конструктор GameData с умолчаниями — область RW 0x642A00–0x6448xx (например, `mov [esi+0x13C], bl` RW 0x642C51); деструктор — RW 0x643D63+.
- Сохранение (xfer) GameData: RW 0x540800 (вызывается виртуально, `jmp [edx+0x6C]` RW 0x5407FC), блочные помощники в области RW 0xA28B00+ (шаблон `mov ecx,[esi]; mov eax,[ecx]; call [eax+0x28]` — Xfer).
- Парсеры-строки таблицы: `0x42E558` parseBool (пишет байт), `0x42EC5E` parseInt (пишет dword), `0x42ED00` parseReal (пишет float), `0x42EE5E` parseAsciiString, `0x42ECB2` parseInt-вариант с доп. аргументом, `0x73A396` пара float (min/max).
- Поиск чтений: полный проход capstone по `.text` (2 701 800 инструкций) с восстановлением базового регистра до `mov reg, [0xDE4364]` в пределах функции (скрипт сессии, не коммитится).

Обозначения вердиктов: `RotWK читает (логика)` / `RotWK читает (клиент)` — чтение симуляцией / клиентом (отрисовка, звук, UI); `RotWK не использует` — парсер пишет поле, но чтения нет или оно только у деструктора/копии/save; `не определено` — цепочка не замкнута (детали по полю).
