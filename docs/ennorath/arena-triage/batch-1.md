## How "done" was determined, and what reset cost

Pipeline (all disassembly of `game.dat` via `python tools/mod/rw.py workspace/RotWK/game.dat dis <addr>`,
a PE + capstone harness; seeds = E8 call targets plus every image u32 pointing into
`.text`, decoded function-first from function entries, ret/int3-terminated, so mid-instruction
starts cannot silently shift the decode phase — an earlier attempt decoded blindly from `.text`
and produced plausible-looking garbage (`in al, dx` rivers); every address cited here was
decoded from a confirmed function boundary):

1. Whole-image byte/string scans (proof of absence, e.g. the WinApi string scan in row 2).
2. Parser field tables (rows: `{userData, prevOffset, name, parserFn}` — offsets are carried by
   the *next* row; verified against BFME2 decomp offsets for 26+124 rows pre-reset).
   In-repo artifact: `engine/data/rotwk-201/field-tables.json` (extracted earlier, still valid;
   every row cited from it below was re-read from the file today). Module registry cross-check:
   `engine/data/rotwk-201/module-registry.json`.
3. Reachable-code scan for register-base reads/writes of each offset
   (`mov r32/r64, [reg + off]`, `lea`, bit tests), then class attribution of the containing
   function via harvested vtables (>=4 consecutive `.text` pointers in `.rdata`, stub-constant
   match) plus registry vtable VAs.

**Workspace reset.** Between two working sessions the sandbox was re-materialized from git:
`/tmp`, the `.venv`, and `workspace/` (including `game.dat` itself, the clone of
open-bfme-2 and the extracted audit) were gone. What survives is the repo (field tables and
module registry above) and the re-clone of the decomp. Consequences, honestly:

- Every address below was gathered with working tools **before** the reset and is cited as
  recorded. The two `читает` rows (#11, #22) and the `RotWK не использует` row (#2) were
  verified instruction-by-instruction before the reset. Every other row is `не определено`
  and says where the evidence ran out — in several of those rows the pre-reset scan found
  *candidate* hits that are listed as findings, not as verdicts, because class attribution
  failed (same offset reused by unrelated classes is the dominant collision).
- Nothing was re-verified after the reset, and nothing should be trusted on this page beyond
  what each row states. The reviewer re-checks addresses anyway.
- To re-verify any row: restore `workspace/RotWK/game.dat` (md5 `daed3668…`), reinstall
  `pefile` + `capstone`, and disassemble at the cited addresses from their function starts.
