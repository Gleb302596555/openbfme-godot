# Подсистемы, которых не хватает Ennorath

Решение владельца, 2026-11-02: записи в [PROBLEMS.md](PROBLEMS.md) это симптомы. Портируем механизмы, из-за которых они появляются, сначала [проверка всех кнопок](BUTTON_SWEEP.md), затем подсистемы. Новая жалоба привязывается к подсистеме и не берётся отдельной задачей ([правило](../ENNORATH_FACTION_PLAN.md), раздел «Список проблем владельца»).

## Откуда числа

Перепись данных мода от 2026-11-02, профиль `workspace/games-en` + `workspace/mods-en`, 11 фракций. Скрипты `census.py`, `matrix.py`, `press.py`, `stops.py` в `workspace/ennorath-audit/tools/` (в Git не входят), результат в `workspace/ennorath-audit/local/census-2026-11-02/`.

- Граф доступности завышает числа: это порядок величин, не знаменатель.
- Число показывает, сколько данные требуют от механизма, а не сколько сломано. Что сломано, покажет матрица.
- Связь жалобы с подсистемой в этом файле это INFERENCE, пока причина не доказана.
- Текст в `STOPS.md` местами устарел, поэтому состояние ниже проверено по коду там, где указан файл.

Всего достижимо: 2809 кнопок, 902 силы, 2708 объектов, 2115 видов оружия, 664 улучшения.

## 1. Кнопки, которые нажимает логика

Самый дешёвый пробел, виден только на моде.

- **Требует мод.** ИИ и DoCommandUpgrade нажимают HORDE_TOGGLE_FORMATION (27 записей, например Command_ToggleFormationGondorFighter, Command_MountToggleBlackrider) и FIRE_WEAPON (10, например Command_ChargeAttack). Плюс WAKE_AUTO_PICKUP, он уже работает.
- **Состояние.** В Object::doCommandButton эти типы только считаются неперенесёнными: [ObjectDoCommandButton.cpp:375](../../engine/src/GameLogic/Object/ObjectDoCommandButton.cpp#L375), S-5305. Также не сделаны EXIT_CONTAINER, EVACUATE, ONE_RING, CREW_EVACUATE, ворота, HORDE_SET_FORMATION, TOGGLE_WEAPON, REVIVE, ремонт.
- **Почему upstream не закроет.** По S-5305 чистая игра нажимает логикой только TOGGLE_WEAPONSET, PLAYER_UPGRADE и SPECIAL_POWER.
- **Что делать.** RW 0x696FD2 и формы с целью RW 0x697890 / 0x6979D9; сначала типы, которые реально жмёт мод. Сверить ATTACK_MOVE (149 записей от ИИ) и SET_STANCE (1711 записей): дойдут ли они до эффекта, в этой переписи не проверено.
- **Проверка.** Второй вход матрицы, сценарий на настоящей кнопке мода.

## 2. Цепочка способностей

Самая большая часть мода и главное неизвестное.

- **Требует мод.** 1261 кнопка `SPECIAL_POWER`, 188 `SPELL_BOOK`; 783 записи `SpecialAbilityUpdate`, 1358 `OCLSpecialPower`, 2383 `SpecialPowerModule`.
- **Состояние.** Общая причина сбоев не установлена. На чистой игре часть прогонов проходит (FACT-A/B/C), часть стопов открыта: S-529, S-1222, S-1228, S-2006.
- **Что делать.** Ничего не чинить, пока матрица не покажет группы. Если есть массовая причина, она становится этой подсистемой, а порядок меняется.

Отдельно смотреть по матрице: смена формы (`ToggleMountedSpecialAbilityUpdate`), режимы оружия (`WeaponModeSpecialPowerUpdate`), составные герои и их расстановка, герои Кольца и передача кольца, летуны (`GiantBirdAIUpdate`).

## 3. Отклик интерфейса

Логика может работать, а игрок считает, что нет.

- **Звук.** Хоткей вызывает тот же `pressButton`, что и нажатие ([InGameHud.cpp:150](../../engine/src/GameClient/InGameHud.cpp#L150)), значит, звук теряется не при выполнении команды (INFERENCE). Найти, кто в RW запускает звук кнопки и голос, и перенести это в общий путь нажатия. Отдельно разобрать звук применения сил, `InitiateAtLocationSound` и фильтр `player` (S-200, записи P-23, P-24).
- **Радиальные меню.** S-280, S-3803: хоткеи пунктов радиального меню.
- **Линии приказов.** Отрисовка очереди приказов, зависит от п. 4.
- **Номера групп над юнитами.** По поиску по именам кода не найдено (INFERENCE): проверить в RW.
- **Выбор нейтральных объектов.** Крипы, просмотр в палантире (P-28).

Проверка: звено 8 матрицы и звуковой тест через `SimulatedAudioDevice`. Что услышит игрок, проверяет владелец.

## 7. Частицы-модели и проекции

- **Требует мод.** 343 определения `Type = DRAWABLE` (338 уникальных имён; 313 упоминаются в INI мода, 167 определений / 165 уникальных достижимы по графу 11 игровых фракций) против 135 в чистой RotWK 2.01 и 121 в BFME2 1.06 (S-195). `TERRAIN_PARTICLE` (тип 6) в Ennorath и в обеих чистых играх не используется (0 определений) и не переносится (остаётся за S-195).
- **Состояние.** Перенесено (обе редакции): мост `RenderObjectDraw` (`MODULE_RENDER_OBJECT_DRAW`) → `ParticleDrawBuilder` (`DrawBatch::DRAWABLES`) → дочерний `W3DInstancer` в `FXPlayer`:
  - **Модель на частицу**: `ParticleName` без суффикса `.w3d` (4 символа с конца, `RenderParticle::RenderParticle` RW 0x5FBBC4 / BFME2 0x005FC49D `RenderParticleConstructor.cpp`, `RenderObjectDrawModule::modelName` RW 0x964A1C / BFME2 0x00562BF8). В `ParticleSystem::isParticleInvisible` (RW 0x5F449F / BFME2 0x005F4E2D) частица `PARTICLE_TYPE_DRAWABLE` с W3D-объектом (`+0x8C`, `RW 0x5F44A2`) никогда не отбраковывается по спрайтовому шейдеру (`shader >= 8`).
  - **Трансформация**: `RenderObjectDrawModule::doParticles` (RW 0x964C00 / BFME2 0x00562DDB `RenderObjectDrawModuleDoParticles.cpp`): до 512 видимых частиц на систему (`!isParticleInvisible`), базовая матрица системы `transform()`, вращение `PARTICLE_ROTATION_OFF` / `X` / `Y` / `Z` / `V` на угол `angleZ` с домножением на базовый поворот при `!isLocalIdentity()`, трёхосевой масштаб `size[0..2]` с отсечкой `>= 0.0001f`, перенос `p.pos`, ветвь `SinkOnTerrainCollision` / `SinkRate`.
  - **Цвет и прозрачность**: по `Shader` системы (`RW 0x965217..0x9652D3`): `W3D_EMISSIVE` → `SetEmissive(color * alpha)` (RW 0x50E040 / BFME2 0x0050E643), `W3D_DIFFUSE` → `SetDiffuse(color * alpha)` (RW 0x50E413 / BFME2 0x0050EA16), `W3D_ALPHA` → `SetOpacity(alpha)` (RW 0x50E244 / BFME2 0x0050E847), прочие (`ALPHA`, `NONE`) оставляют материал модели без переопределения (`opacity = 1.0`).
  - **Анимация**: циклическая скелетная анимация `<model>.<model>` при наличии в `.w3d` (`RW 0x5FBD33` / `BFME2 0x005FC60F`, `Set_Animation(anim, 0.0f, ANIM_MODE_LOOP)`) и текстурные мапперы (`LinearOffset`, `SineLinearOffset` у `EXCldBrkRays.W3D`) через `W3DInstancer`.
  - **Не перенесено**: `TERRAIN_PARTICLE` (тип 6, 0 в Ennorath и чистых играх, остаётся S-195); случайный выбор группы `MultiRenderObjects` (RW 0x964A1C / BFME2 0x00562BF8, 0 определений в Ennorath и чистых играх; при включении берётся `Object1` и пишется `unverified`). Круг света `PartTheHeavensUpdate` уже перенесён (S-7093 закрыт).
- **Что делать.** Выполнено (обе редакции): мост `RenderObjectDraw` → `W3DInstancer` перенесён и проверен тестами; стоимость `ParticleDrawBuilder::build` на 225 системах `CloudBreakRays` — ~0.04 мс/кадр; подтверждено владельцем в игре (2026-11-02).
- **Проверка.** Только отображение, симуляция не меняется. Просмотр владельцем: лучи Cloud Break (P-18), обломки.
