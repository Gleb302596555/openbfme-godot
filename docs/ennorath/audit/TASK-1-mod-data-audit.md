# Задача 1. Сверка данных мода с портом

Решение владельца 2026-11-04. Очередь: после режима для тестов (ветка `agent/claude/test-sandbox`). Идёт первой, задача 2 опирается на её результат.

## Цель

Найти будущие проблемы до того, как их заметят в игре: каждое поле INI Эннората, которое порт не читает или читает и не использует.

## Что сделать

1. Пройти по всем INI мода (база 1.9.8.1, `workspace/mods-en/Ennorath`, архивы мода поверх RotWK 2.01; правило из `ennorath-patch-note`: последнее слово за файлами мода).
2. Составить полный список: блок (Object, Weapon, Armor, FXList, ParticleSystem, CommandButton, SpecialPower, Upgrade, ...), модуль (`Behavior = X`, `Draw = X`, `Body = X`, ...), каждое поле и его значения. Ни одного пропуска: если поле не распознано, это отдельная строка отчёта.
3. По каждому полю отметить одно из трёх:
   - **читается и используется**: порт парсит поле, и логика или клиент его читает;
   - **читается, не используется**: поле разобрано, но его никто не читает (или есть стоп `S-xxxx`);
   - **не читается**: парсер его не знает, пропускает молча или с ошибкой.
4. «Используется» определять по коду, а не по названию: поле хранится в модуле, и это значение где-то читает код за пределами парсера.
5. Отсортировать по числу объектов мода, которые используют модуль или поле, чтобы сначала шло то, что встречается чаще всего.

## Результат

- Таблица (csv или md) с колонками: блок, модуль, поле, примеры значений, число использований в моде, статус, место в коде порта, стоп если есть.
- Короткая сводка для владельца: сколько полей в каждом статусе и первые 20 по важности.
- Повторяемость: скрипт в `tools/mod/` запускается после каждого патча мода и показывает разницу с прошлым прогоном.

## Опора

- Уже есть частично: `docs/ennorath/MODULE_GAPS.md` (по модулям, не по полям).
- Таблицы полей RotWK в `game.dat` (field table, например RW `0xC71D68` для ActiveBody): по ним сверять, какие поля понимает сам RotWK. Поле, которого нет в таблице RotWK, мод игнорирует и в оригинале, это не наша проблема.
