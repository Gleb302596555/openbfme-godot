## Шаг 1. Две известные ошибки инструмента (сначала их)

1. **Звуковая таблица объекта.** `Grammar.object` и `rotwk_tables()` в `field_audit.py` берут только `objectTable` из `engine/data/rotwk-201/field-tables.json`. Движок читает Object по двум таблицам: `objectTable` и `audioTable` (`engine/src/Common/Thing/ThingFactory.cpp:138-174`). Поэтому `VoiceSelect`, `SoundOnDamaged`, `VoiceMove` и другие звуки ложно попали в `not-in-rotwk`. Добавь строки `audioTable` в обе функции. Добавь в тест поле из звуковой таблицы: тест должен падать без правки. После прогона разбери, что осталось в `not-in-rotwk`, и для каждого оставшегося поля проверь, что его действительно нет ни в одной таблице RotWK.
2. **Чтение прошлого TSV.** `write()` (сравнение с прошлым прогоном) и `load_coverage()` читают TSV через `csv.DictReader` с кавычками по умолчанию. Значения мода с кавычками склеивают строки (при чтении получилось 4155 строк вместо 4362). Нужен `quoting=csv.QUOTE_NONE`. Проверь: число строк при чтении равно числу полей из вывода.

После обоих шагов: тест зелёный, прогон, коммит.

Правила:
- **Сначала ищи общий механизм.** Если у многих строк один и тот же парсер (например, `parseModelStateParticleSysBone`, `parseShadow*` в `W3DModelDraw.cpp`, `Parsers::*` в `EvaEvents.cpp`), научи инструмент проходить этот парсер (`_infer_custom_members`, `parser_rows`) и добавь случай в тест. - **Ошибся инструмент — правь инструмент, а не таблицу.** Каждая правка: тест, который падает без неё (проверка на прошлом коммите, как в прошлой сессии), затем прогон и коммит.
