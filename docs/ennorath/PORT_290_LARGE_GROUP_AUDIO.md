# Port 290: Sound-block selection in RotWK 2.01

`LiveGameAudio::LgaRuntime::apply` already distinguishes current vs stored model/status/stealth and the signed frame gate (RW 0x7EF032, RW 0x7EEF0D, RW 0x7EF0A1). Do not add another filter in the object module. The divergence starts where the Sound block receives a qualifying member: the port replaces an entry indexed by ObjectID. RW 0x971326 tests the keys, reads current position and unsigned word weight, increments block total, then either updates the grids or records the contribution until they exist. RW 0x971392 uses stored position for the inverse operation.

RW 0x971FA7 compares the total against StartThreshold before allocating absent grids, limiting new allocations with a shared flag after frame one. RW 0x9715BA constructs four grids, using RW 0x97037B origins (0,0), (-Size/2,0), (0,-Size/2), (-Size/2,-Size/2). RW 0x9D7BC8 builds each buffer separately in row-major order, centres at origin + (index + 1/2) * Size. RW 0x9D76E3 truncates relative coordinates and bounds-checks column and linear index. RW 0x9712C9 applies the contribution to every non-null lookup. RW 0x9D7DF6 computes preferred xy from surrounding cell weights, not from the centroid of members. DONOR BFME2 0x005C8876 (`LargeGroupAudioGridCell.cpp`) identifies the preferred-position routine independently.

## Equal candidates: exact selection depends on runtime inputs outside the INI

RW 0x971121 inserts the changed cell pointer into the dirty list using RW 0x9709DA → RW 0x42C22B (unsigned pointer lower_bound), not a logical grid number. RW 0x971FA7 first examines playing cells below StopThreshold or next to a heavier cell and handles displaced sounds. It then sorts dirty cells (call at 0x972229). RW 0x9701ED compares weight descending and the upper nibble of +0x47 ascending, with **no final grid/coordinate comparison**. For a short list (at most 16), RW 0x970F56 → RW 0x970D5E uses insertion sort. The cell-start loop at 0x972238 skips locked cells and breaks below StartThreshold. In particular, equally ranked, initially unlocked overlapping candidates are not distinguishable by map/member inputs alone: the order of their separately allocated buffers can matter. Using the host heap as a test oracle or asserting a grid-number tie-break as retail would both be wrong. A test with a strictly heavier candidate avoids this ambiguity but cannot establish exact parity for the common single-cluster tie.

Owner decision: use (grid allocation order, row-major index) only after both retail rank keys compare equal (S-7512). RW 0x9D7D1E builds the upper nibble by counting null neighbour pointers. RW 0x9D7D78 maintains the lock on the cell and its eight neighbours. Displaced events choose among those eight and their old cell before fresh starts; returning to the old cell preserves the glide count, changing cells loads the duration from the map. All new state belongs to the audio client. No CRC or simulation snapshot format changes.
