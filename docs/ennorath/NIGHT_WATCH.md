# Что смотреть в ночном прогоне

Правки, которые перенесены в `main` по разделу 7а [PROCESS.md](PROCESS.md): проверены узким тестом и владельцем, но полный прогон их ещё не видел. Ночной агент читает этот файл **до** разбора прогона.

## Как вести

- Строку добавляет агент, который сделал правку, в той же ветке, до переноса.
- **Что изменено**: файлы и механизм, а не пересказ задачи.
- **Местная или движок**: местная — одна кнопка, способность, модуль, панель; движок — общий механизм (цикл кадра, движение, бой, приказы, ИИ, производство, ввод, сохранения, сеть, загрузка данных, отрисовка целиком, код больше чем одного модуля). Сомнение — движок.
- **Может сломаться**: какие объекты, системы, хэши, сохранения задевает правка, даже если узкий тест прошёл.
- **Смотреть ночью**: шаблоны имён тестов (`-tc=`), которые первыми покажут поломку.
- **Ночь**: `ждёт` → `прошло <дата>` или `упало <дата>: <тест>, P-<номер>`. Меняет ночной агент.

## Как разбирать ночью

1. Падения, которых нет в [TEST_BASELINE.md](TEST_BASELINE.md), сравнить со строками `ждёт`: имя теста из «смотреть ночью» или система из «может сломаться».
2. Совпало: в строке `упало`, запись P-<номер> в [PROBLEMS.md](PROBLEMS.md), в [TOP20.md](TOP20.md) статус проблемы `исправлено, ждёт: исправления падения`, первая задача ветки, которая внесла правку.
3. Не совпало ни с одной строкой: обычный разбор по разделу 7 (падение относится к веткам, перенесённым за день).
4. Прогон полный (раздел 7: нет `CRASHED`, `skipped` равно числу `doctest::skip`) и упавших по строке нет: `прошло <дата>`; `проверено` в TOP20 становится окончательным. Неполный прогон строки не закрывает.
