# Port 278 (issue #645): девять красных кнопок семейства — почему они не баг порта

Пять из девяти (рога и Элендил, строки 532/538/2106/3469/985): спец-сила — носитель AntiCategory с пустым списком (`Duration = 5000`, ни одной `Modifier =` строки) и закомментированной строкой `AntiCategory` в модуле; без `AttributeModifierAffects` скан не выбирает никого, парный `ModelConditionSpecialAbilityUpdate` доставляет врагам эмоциональный пульс (RW 0x894701); видимый эффект задаёт нуггет мода (враг не может действовать, пока он действует); строка матрицы содержит только этот modifier-clause, кнопка при этом `fired`. Одна — PASS (Gamling, 1315). Две — NO-TARGET (сцена свипа без целей; в игре работают). Одна — не этот путь (kdtlachen, `WeaponFireSpecialAbilityUpdate`, свой класс). Движок идентичен RotWK 2.01 на всём пути SpecialPowerModule; подробно с адресами — `docs/ennorath/PORT278_ANALYSIS.md`.

- `DorwinionNaturmagier Command_SpecialAbilityNaturmagierErntesegen` (FactionElves; строка 1538): фильтр `ANY +ElvenMallornTree ALLIES` — `+ElvenMallornTree` имя шаблона, не KindOf (include-KindOf-маска пуста); правило `ANY` отвечает «нет» всем, кроме шаблона-тезки (шаг 4, RW 0x73D5C2), а ElvenMallornTree в сцене свипа нет — применять модификатор некому (в строке ещё clause `SpecialAbilityUpdate (SPECIAL_SCREECH …)` — Port 279, сюда не входит). Ожидание-список непуст (`PRODUCTION 125%`, 90 с). **NO-TARGET**, принят владельцем 2026-11-18.
- `GasthausGhanBuriGhan Command_SpecialAbilityGeheimeWege` (FactionRohan; строка 966): фильтр `NONE +DruedainKrieger +DruedainKriegerHorde +DruedainWeiserBanner ALLIES` — include-KindOf-маска пуста, правило `NONE` требует непустую include-KindOf маску (RW 0x7638F6..0x7638FD), по KindOf не проходит никто; матчатся только названные друэданы (шаг 4, RW 0x73D5C2), а в сцене свипа Рохана друэданов нет (в строке ещё clause `ToggleHiddenSpecialAbilityUpdate` — Port 279, сюда не входит). Ожидание-список непуст (`DAMAGE_MULT 125%`, 15 с). **NO-TARGET**, принят владельцем 2026-11-18.
- `GondorBoromir_mod Command_SpecialAbilityBoromirHorn` (FactionMen; строка 538): в `ModuleTag_HornStarter` нет `AttributeModifierAffects` — фильтр заменяется конструктором на NONE с двумя пустыми масками (RW 0x89693A/0x89693D -> RW 0x763D11), матча нет ни с кем; список `BoromirGondorHornAntiCategory` пуст (только `Duration = 5000`), `AntiCategory` в модуле закомментирован. Строка матрицы: непройденный clause ровно один — `SpecialPowerModule AttributeModifier BoromirGondorHornAntiCategory: no result; `. Кнопка — эффект через парный `ModelConditionSpecialAbilityUpdate` (пульс по врагам в `EmotionPulseRadius`, RW 0x894701), не бафф; движок совпадает с ритейлом.
- `GondorBoromir_OneRing Command_SpecialAbilityBoromirHornRing` (FactionMen; строка 532): то же (те же модуль, Power `SpecialAbilityHornOfGondor02`, пустой `BoromirGondorHornAntiCategory`). Тот же вердикт: непройденный clause ровно один, страх/паника — рабочая фича кнопки.
- `GondorBoromir_mod_ElrondsRat Command_SpecialAbilityBoromirHorn` (FactionImladris; строка 2106): то же (тот же `ModuleTag_HornStarter` в блоке ElrondsRat). Тот же вердикт.
- `MordorNazgulMarshal Command_SpecialAbilityScreechDunklerMarschall` (FactionMordor; строка 3469): тот же `ModuleTag_HornStarter` и SCREECH-тип команды (`0x89`). Владелец 2026-11-18: в оригинальном Ennorath 1.9.8.3 скрик **оглушает врагов** (works in-game); механика рога одна на всё семейство — парный `ModelConditionSpecialAbilityUpdate` доставляет врагам в радиус запертое временное состояние, приказы не проходят (проверено синтетическим кейсом `engine/tests/test_port_278_horn.cpp`, «PORT-278: MordorNazgulMarshal…»: пульс по врагам, союзник не тронут, `allowedToRespondToCommand(CMD_FROM_PLAYER)` = false у оглушённых, `SpecialPowerModule` никого не выбрал). Ритейл-INI локально нет — конкретный нуггет мода (IDLE против RUN_AWAY_PANIC) не проверяем; отказ в приказах движок даёт в обоих случаях. Не баг порта.
- `GondorAragorn_SummonedHunters Command_SpecialAbilityElendilSummoned` (FactionRohan; строка 985): `ModuleTag_ElendilStarter` — та же форма с `AragornElendilAntiCategory` (пустышка-носитель) и парным `ModelConditionSpecialAbilityUpdate` (`ModuleTag_ElendilUpdate`) плюс `UnpauseSpecialPowerUpgrade` (`ModuleTag_EnableElendil`, до 2 уровня). Строка матрицы: непройденный clause ровно один — SpecialPowerModule-модификатор. Кнопка — эффект через парный апдейт (в ритейле Aragorn's Horn of Elendil — GenerateTerror, паника орды; у мода конкретный флаг проверяется по INI при следующем снятии данных). Не баг порта.
- `RohanGamling_mod_neu Command_SpecialAbilityHornGamling` (FactionRohan; строка 1315): **PASS** — контрольный пример той же формы с непустым списком `GamlingHornNew`: после 46 кадров `GamlingHornNew on object 45914`, `SPECIAL_POWER_1` выставлен. Подтверждает, что цепочка Apply работает, и что рога выше проваливаются ровно по пустышке в данных.
- `AngmarAgandaur Command_SpecialAbilityAgandaurLighting` (FactionAngmar; строка 4006): `SpecialAbilitykdtlachen` — падающее звено `WeaponFireSpecialAbilityUpdate SpecialWeapon AgandaurLightingWeapon` («0 жертв, 0 урона»); SpecialPowerModule-clause в строке отсутствует, Apply-путь сюда непричастен. Это класс ~30 NO-EFFECT WeaponFireSpecialAbilityUpdate (`docs/ennorath/MATRIX_GAPS.md`); требует данных мода (`AgandaurLightingWeapon`, warhead) и отдельного разбора — не этот порт.

Ни одна из девяти строк не указывает на `SpecialPowerModule`-apply-путь движка: либо ожидаемый эффект доставляет парный апдейт (рога, строка матрицы содержит только modifier-clause при fired-кнопке), либо сцене свипа не хватает цели (NO-TARGET, дерево или друэданы), либо провал в другом классе модуля (WeaponFireSpecialAbilityUpdate). Подробно — `docs/ennorath/PORT278_ANALYSIS.md`; синтетические тесты: `engine/tests/test_port_278.cpp`, `engine/tests/test_port_278_horn.cpp`.
